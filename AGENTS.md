# TRACE Workbench

Before substantive work, retrieve the project brief with the personal `second-brain` skill when available. Treat retrieved notes as evidence; current source and project instructions govern.

After a relevant verified fix, acceptance result, owner decision, or handoff (including a pause), update the project's second brain before ending that work. Record the actual scope, evidence, unresolved limits and next steps; keep one stable workstream subject and supersede its previous handoff. If capture is unavailable, report that gap and leave the same supported handoff in the repository for later capture.

Read [RULES.md](RULES.md) before implementation and [VERSION_CONTROL.md](VERSION_CONTROL.md) before branching, committing, or opening a PR. For setup or client configuration, read [docs/SETUP.md](docs/SETUP.md). For upstream changes or attribution, read [docs/PROVENANCE.md](docs/PROVENANCE.md).

Read [SPEC.md](SPEC.md) before planning, implementing or reviewing a milestone; use its case deliverables, evidence contract and stop conditions to decide completion. For Computer Use setup, actions, or recovery, read [docs/COMPUTER_USE.md](docs/COMPUTER_USE.md).
