# How to build and benchmark TRACE Computer Use on Windows

This guide rebuilds the TRACE skill and Windows executor, then compares it with bundled Codex Computer Use on one owned WinForms control. The implementation is in [PR 172](https://github.com/mogesjohnson/trace-workbench/pull/172) and [PR 173](https://github.com/mogesjohnson/trace-workbench/pull/173).

## Rebuild the skill from an empty directory

1. Create a Node project. Use the Node versions in [package.json](package.json) and Windows x64 with the .NET 10 SDK and Desktop runtime. Use [the lockfile](package-lock.json) for exact dependency versions. The Windows executor uses MCP 2.3.1 over stdio, Zod schemas and winapp CLI 0.7.1. [Winapp version and hashes](src/computer/winapp-pin.json)
2. Create `trace-computer-use/SKILL.md`. Add YAML frontmatter with `name: trace-computer-use` and a `description` covering the tasks it handles. In the body, route to a connected application API when it can perform the task, then to structured browser tools for web targets, then to native input for Windows windows. Write the native sequence doctor → exact discovery → open → observe → one action → verify → close. Explain how to choose image mode, depth, scope and response size. [Canonical skill](skills/trace-computer-use/SKILL.md)
3. Add the three supporting references. Put capability selection and missing-tool handling in [readiness and routing](skills/trace-computer-use/references/readiness-routing.md). Put freshness, owned dialogs, uncertain delivery and cleanup in [operation and recovery](skills/trace-computer-use/references/operation-and-recovery.md). Put test gates and effect verification in [acceptance](skills/trace-computer-use/references/acceptance.md). Record the four authored files in [the manifest](skills/trace-computer-use/manifest.json) with their raw-byte SHA-256 hashes.
4. Implement the seven public tool schemas in [server.cjs](src/computer/server.cjs). Open accepts a returned window ID. Observe accepts a session ID and requested evidence. Act accepts the latest observation ID, one strict action and the requested refresh form. Send structured state and a separate MCP image block for each screenshot. Store each image's content index and physical dimensions in the state so clients can bind it to the observation.
5. Build the [controller](src/computer/controller.cjs) around one leased target. Pin HWND, PID, process creation time and Windows session. Serialize desktop work. Store the observation ID, geometry, tree, scope and expiry on the server. Consume the ID before dispatch. Revalidate window and element identity before input and verify effects against application state. Use fresh evidence and the same binding when following owned dialogs.
6. Implement the [Windows adapter](src/computer/winapp-backend.cjs) with public Win32, DWM and UI Automation surfaces. Use window-scoped capture, normalize physical bounds, and bracket the capture with identity and geometry checks. Reject occluded points. Generate fresh evidence after an action. Separate input delivery from the result of the subsequent refresh so a lost refresh cannot lead to an automatic replay.
7. Build the [native session owner](native/TraceSupervisor/Session.cs) with private inherited stdio. Acquire the exclusive desktop lease, start the visible [indicator](native/TraceActivityIndicator/Program.cs) and install physical Escape handling. Run mutating providers in kill-on-close jobs. Record declared inputs and the child identity before resuming the process. On interruption, drain or terminate owned work and verify input release. Retain durable recovery when cleanup is uncertain.
8. From the repository root, run `npm ci`, `npm run computer:setup -- --plan`, `npm run computer:setup -- --apply` and `npm run computer:doctor`. Setup builds and hashes the native helpers under `.runtime/`. Run `npm run computer:config -- --plan --client codex --client claude_code`, then apply the same scope with `--apply`. Reload MCP in both clients. Each client discovers the authored skill and launches `bin/trace.cjs computer mcp` over stdio. [Install and connect](docs/COMPUTER_USE.md#install-and-connect)

## Compare the two skills one step at a time

Scope this comparison to a Windows window that is already open. TRACE also routes work to connected APIs and browser tools. The Codex reference is the bundled Windows Computer Use skill and its supported `@oai/sky` window API. TRACE's authoring entry point is [its skill](skills/trace-computer-use/SKILL.md), and [the MCP reference](docs/COMPUTER_USE.md) defines its runtime contract.

| Step | Codex Windows Computer Use | TRACE Windows Computer Use |
| --- | --- | --- |
| 1. Initialize | Import `{ sky }` from `@oai/sky` in a persistent `node_repl` session. The packaged JS proxy asks the trusted runtime for its supported methods. | Discover the MCP tools and call `trace_computer_doctor` before starting a native session. Doctor reports provider readiness and supported actions. |
| 2. Select exactly one window | Call `sky.list_windows()`, or find the app and its windows with `sky.list_apps()`. Select the exact returned window. Use `get_window({ id, app })` to rehydrate the returned identity when needed. | Narrow `trace_computer_list_windows` by process name or title, then choose the exact returned ID. When launching is needed, rediscover the returned target. |
| 3. Prepare the target | The guidance example calls `activate_window` once during setup. The API also documents that input methods activate their own target. | Open the exact window with `trace_computer_open_session`. The native supervisor owns the desktop lease and indicator. The controller and native backend revalidate the target at input time. |
| 4. Observe | Call `get_window_state({ window, include_screenshot: true, include_text: true })` once for image and tree. Save the returned window, tree index, and screenshot ID from that state. The wrapper makes one native state request and emits its images through the host. | Call `trace_computer_observe` in full mode with `screenshot: "full"` and depth 2. Retain the session ID, single-use observation ID, selected element ID, and physical bounds. The installed 2.3.0 backend reads geometry, UIA, capture, related windows, identity and focus through multiple supervised calls. |
| 5. Click once | Call `sky.click` with the returned window and current element index, adding the screenshot ID on the benchmark path. The JS wrapper issues one element-click request. | Call `trace_computer_act` with the session ID, observation ID, and exact element ID. In 2.3.0 this repeats target and geometry validation, prepares activation, checks pointer occlusion, then dispatches the click. |
| 6. Refresh immediately | In the same cell as the click, call `get_window_state` again with both flags. Use the fresh evidence for the next decision. | `act` performs the refresh internally. Pass `returnObservation: "full"` to get the complete result with its inherited screenshot setting. |
| 7. Verify the effect | Compare the fixture's independently written counter before and after. | Apply the same counter check. An action receipt and fresh observation are separate from proof of the intended effect. |
| 8. Recover and release | Recover a lost window binding from returned identity or fresh discovery. Reobserve after uncertain delivery. The packaged client has host end-of-turn handling. | Classify `not_dispatched` and `unknown` separately, then verify uncertain delivery before any new action. Close the session and confirm lease release and native cleanup. |

The Codex screenshot-only default skips accessibility text. The benchmark explicitly requests both on both screenshot-backed reads. TRACE's image-free full observation still grants one action. Its separate accessibility-only and screenshot-only modes are evidence-only. Use the complete screenshot-backed paths when evaluating parity. A screenshot-free element click in the original Codex warm-up failed for missing coordinate geometry, with no observed effect.

## Warm worker and guarded click

1. Rebuild the bridge for `net10.0-windows10.0.19041.0`. Pin the WinApp UI Automation SDK to 0.7.1 and dependency injection to 10.0.0. Lock the NuGet packages and verify the bridge and dependency hashes in the local build manifest. Run `npm run computer:setup -- --apply` and `npm run computer:doctor` on the exact checkout. [SDK and setup changes](https://github.com/mogesjohnson/trace-workbench/pull/175)
2. Start the bridge read worker inside a supervisor-owned kill-on-close Windows Job Object with private inherited stdio. Start it lazily, serialize requests and bound output, time and UIA traversal. Terminate and join the job on stop, timeout or close. Read-only commands carry no input declaration. [Supervisor ownership](https://github.com/mogesjohnson/trace-workbench/pull/176)
3. In the worker, pin HWND, PID, process creation time and Windows session. Start a new HWND-only WGC capture and collect the current UIA tree while it runs. Require fresh pixels, exact physical frame dimensions, a readable root and matching final geometry. Crop the frame to its intersection with the UIA root, encode PNG, read focus and related-window context, and return a single evidence receipt. Scope, document and related-image requests retain the compatible CLI path. [Warm observations](https://github.com/mogesjohnson/trace-workbench/pull/177)
4. For an eligible single click, take the point and element runtime ID from the server-retained observation. The native command checks lifetime and geometry, activates the window, positions the cursor, and rechecks the element and hit target before sending one declared down/up pair. Keep the recovery record and require confirmed release. An explicit refusal before SendInput is `not_dispatched`. An interrupted operation after admission may be `unknown` and requires effect verification. [Guarded click](https://github.com/mogesjohnson/trace-workbench/pull/178)
5. Route eligible controller requests directly to the worker with its own identity and geometry checks. Keep controller-level identity checks for other paths. The measured cycle then makes three native requests: one read, one click and one refresh. [Controller routing](https://github.com/mogesjohnson/trace-workbench/pull/179)
6. Use the public `IUIAutomation::ElementFromHandleBuildCache` and `ElementFromPointBuildCache` APIs for the exact window and point. Keep a native UIA cache request on the worker thread, project the current tree to TRACE's existing schema, and retain runtime IDs on the server. Resolve control types from Windows UIA identifiers and release COM objects, VARIANT values and SAFEARRAY data after each use. Cap the projection and fall back on unsupported reads. [Direct UIA cache](https://github.com/mogesjohnson/trace-workbench/pull/180)
7. Start a one-shot click process while the observation is running. Initialize its COM cache before writing the readiness line. Accept LF and CRLF in the handshake. Hold the child in its own kill-on-close job, persist its exact identity and declared left button, then send the only input request through the private pipe. Require a drained job and verified input release before returning the click receipt. [Prewarmed click](https://github.com/mogesjohnson/trace-workbench/pull/181)
8. Run the same fixture procedure above with `mode: "full"`, depth 2, a PNG before and after input and `returnObservation: "full"`. Capture per-sample timings and the independent count before and after every click. Verify move and minimize reject stale coordinates. After a fresh observation, require one successful click. Close each lease before handing the fixture to the other provider.

The managed `CacheRequest` acquisition took 185–233 ms warm in the standalone comparison. The direct Windows API took 54–65 ms for the rich request. Reducing the property set in the managed cache did not close the gap. Passing the observed root selector to the SDK capture sometimes selected a 33×33 crop. The worker uses the exact HWND as its WGC source and crops against independently measured frame bounds. Prewarming only the managed click process produced a 728 ms cycle in an exploratory run. The faster click worker uses the direct cache API and a readiness check that accepts Windows line endings.
