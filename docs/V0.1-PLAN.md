## Goal and boundaries

Make TRACE dependable on the existing Windows account, with visible screen takeover, clear activity indication, reliable recovery, and verified agent workflows.

- Use Windows Home and the tested single-monitor configuration. Record actual resolution and DPI for each case.
- Defer background workers, additional profiles, Windows upgrades, and broader monitor/DPI support beyond v0.1. Preserve historical blocked display evidence.
- Use a synthetic REPLAY project with isolated storage. Keep the real library untouched.
- Preserve completed work and evidence. Rerun unfinished cases or behavior affected by new code.

## Implementation decisions

### Input supervision and recovery

- Introduce a source-owned .NET supervisor that owns the desktop lease, input processes, cleanup state, and glow lifecycle.
- Launch mutating native processes inside a Windows Job Object before they execute; prevent input children from escaping ownership. See [Microsoft's process-lifetime mechanism](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects).
- Retain the 15-second operation deadline. On interruption, drain briefly, terminate owned work when necessary, confirm exit, release and verify declared input, stop the glow, then release desktop ownership.
- Persist recovery state before input starts. Unconfirmed cleanup or supervisor death blocks subsequent input across server restarts.
- Add `computer recover --check` and `computer recover --apply`. Validate recorded process identities and input state before clearing quarantine.
- First run a bounded feasibility probe for job assignment, lease exclusion, parent-death detection, and observable pointer/chord cleanup on this account. A failed probe blocks this phase; retain its result without weakening the recovery requirements.
- Reconnect older TRACE servers during migration so acceptance uses one known implementation.

### Public interfaces

- Retain the **six MCP tools** and normal action schemas.
- Use standard MCP cancellation; add no separate cancellation tool or public test-only hold parameter.
- Add optional `accessibilityDepth` to observation: default **8**, maximum **32**. Return a fresh screenshot, element IDs, actual depth, and truncation status.
- Extend diagnostics with supervisor readiness and recovery-required status.
- Keep process-control messages private to inherited stdio. Expose no arbitrary executable launcher or network listener.

### Agent instructions

- Require fresh targeting after a miss, changed geometry, expired observation, or interruption.
- Verify the intended control's focus before typing or shortcuts.
- Release desktop ownership before lengthy analysis or waits.
- Record human interruption separately from product failure.
- Explicitly defer broader display acceptance; preserve its historical blocked receipts.

## Acceptance

### Glow and native behavior

- Preserve the failed glow attempt and Escape-interrupted attempt.
- Resume the interrupted case under a recorded continuation plan with fresh fixture state. Preserve its history and failure budget.
- Require zero initial mouse counts and released input. One reference-executor click must produce count **1**; one TRACE MCP click must produce count **2**.
- Verify unchanged focus, visible glow, normal shutdown, parent-loss cleanup, and confirmed helper exit.
- Complete modal acceptance through explicit session handoff: parent → exact owned dialog → parent. Verify confirmation and native parent-enabled state. Do not rerun the exhausted full harness as another undisclosed attempt.
- Test moved/minimized windows independently: stale input rejects; fresh targeting reaches the intended control once.

### Recovery

Run separate cases for MCP cancellation, timeout, disconnect, Node server death, supervisor death, and failed-cleanup quarantine.

Use a source-owned controlled input provider for deterministic held-input failures through the production MCP/controller/supervisor path. Label that substitution and retain a separate pinned-engine dispatch check.

Failed-cleanup testing independently releases real input before injecting a failed acknowledgement. Confirm quarantine survives restart and prevents another action.

### Codex, Claude, and REPLAY

- Each required host discovers both selected skills, inspects actual evidence, achieves an exact target state, recovers from a rejected action, and closes its session.
- Grok and Gemini live acceptance remain optional and explicitly unverified until exercised.
- Launch pinned native REPLAY in its existing isolated smoke mode, with temporary grants confined to fresh test folders. Provision through its existing acceptance harness; keep credentials local and revoke grants during cleanup.
- Record the owned synthetic fixture, trim the recording, add a callout and privacy blur, place offline test audio, and exercise actual TRACE-driven editor controls.
- Produce **`fixture-demo.mp4`** with verified visual edits, audio placement, duration, codec, and hash.
- Use a second isolated REPLAY instance to record the first editor's exact window, producing **`editor-walkthrough.mp4`** showing edit creation and completed-file playback. First verify the two-instance arrangement with a short feasibility case.
- Identify API operations, TRACE GUI operations, and smoke-mode coverage separately. Use explicit recording IDs for stopping.
- Make no new ElevenLabs requests. Synthetic audio tests mixing, not speech quality or semantic listening.

## Release gates and operating defaults

- Announce desktop takeovers beforehand, keep ownership blocks bounded, and close owned fixtures afterward. Escape stops further computer input.
- Allow one corrective retry after a documented change; unresolved delivery, interference, or cleanup stops that case.
- Every live receipt includes source identity, environment, expected/actual state, artifact hashes, and cleanup results.
- Validate installation from a fresh Windows runner and scratch configuration, including exact backups, idempotence, conflict preservation, and rollback. Identify noninteractive installation coverage separately from live desktop acceptance.
- Publish a source/setup archive, acceptance manifest, and SHA-256 checksums. Verify installation from that exact archive.
- Hosted CI must pass before release. Billing restrictions, unavailable Claude access, or missing prerequisites remain explicit blockers.
