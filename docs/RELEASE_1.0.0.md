# TRACE Workbench 1.0.0

Published 30 October 2026 with direct owner approval. [Download v1.0.0](https://github.com/mogesjohnson/trace-workbench/releases/tag/v1.0.0). The [publication receipt](../evidence/release-1.0.0/publication.json) binds the tested source, passing CI, exact archive and five verified assets. Companion manifests and bundled notes preserve their prepublication snapshot; the public tag and publication receipt close the release gate.

## Changes

- Cleanup requires explicit native confirmation plus normal owner exit. Uncertain results remain visible through controller, MCP and method adapter; checkpoints retain uncertain desktop acquisition even before input.
- Shared validation and diagnostics describe the effective pinned action contract: UTF-16 string limits, supported keys, vertical 120-unit wheel steps and separate configured/native/target readiness.
- Method observations validate the PNG/index/hash/dimensions and exact observation/session/process-lifetime/owner association before exposing remapped images. Association is not semantic image comprehension.
- Fixed-label monotonic diagnostics expose observation-stage time, provider attempts and projection bytes. Unobservable startup/wire/client/model timing remains unavailable; nested times overlap.
- Opt-in immediate read-only verification can reuse a validated post-action frame. Missing, expired, uncertain, insufficient or inconclusive evidence falls back to fresh observation. Final effect checks and future input retain fresh-observation requirements.

The [V1 compatibility contract](COMPUTER_USE.md#v1-compatibility-boundary) stabilizes public wrapper forms and meanings. The action descriptor's `contractVersion: 1` is independent of the package and MCP protocol versions. Pinned winapp 0.7.1, REA 6.7.0, native helper sources and the five-file skill bundle are unchanged.

## Evidence and release gates

Focused synthetic checks cover cleanup projection, limits/readiness, image association, private evidence lifetime and conservative verifier fallback. In-memory MCP/coordinator integration used two captures instead of three for an eligible immediate confirmation, with one input action. This is capture-count evidence, not measured native latency or a new live host/application run.

Required hosted Windows verification must pass for the actual candidate: source checks, test suite, both MCP smoke paths and exact-source archive installation/rollback. An earlier candidate or v0.1.0 CI run does not certify changed archive bytes. Publication evidence must bind the tested commit, CI run, exact archive SHA-256 and published asset digests.

Retained [v0.1.0 acceptance](RELEASE_0.1.0.md) supports its original compatible native/host/application scope. Historical failures, mixed recovery sources, three legacy owner-exit metadata gaps and sampled media-review limits remain explicit. No completed desktop acceptance is repeated by this candidate preparation.

## Install and update

Use the [README setup commands](../README.md#computer-use-setup) and [archive verifier](ARCHIVE_INSTALL.md). Extract the chosen committed source, run `npm ci`, inspect/apply local engine setup, check diagnostics, then inspect/apply configuration. Existing registrations point to an absolute checkout; keep that path available or deliberately reconfigure it using the preservation workflow. Reconnect MCP hosts after code changes.

Configuration verification uses a scratch home: four client registrations, three manifest-owned five-file skill copies, exact backups, idempotence, conflicting/unrelated setting preservation and rollback. Personal installed copies are not changed by source/archive tests. Existing skill guidance remains compatible; no bundle resynchronization is claimed here.

## Distribution and limits

The intended GitHub release contains the exact source/setup ZIP, acceptance manifest, sanitized distribution receipt, release notes and SHA-256 checksums. Reproduce the ZIP with `git archive --format=zip --prefix=trace-workbench/ --output=<archive> <full-source-sha>` in UTC, then compare its SHA-256 with the verified receipt; cross-environment byte identity must be checked. Use the [verifier](ARCHIVE_INSTALL.md) to test those committed bytes. Package, lockfile and `v1.0.0` tag must agree. npm publication remains outside scope (`private: true`).

Windows x64, unlocked normal interactive desktop, supported Node.js and .NET 9 remain required. Readable UIA, image/geometry bounds and recovery guards still apply. Background GUI isolation, broader display transitions, optional live hosts/providers and new gestures remain deferred. Future roadmap labels do not automatically change the package major version.
